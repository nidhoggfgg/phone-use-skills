# 传输安全

[English](transport-security.md) | **简体中文**

## 信任与用户操作

手机所有入口仅使用 HTTPS（TLS 1.2/1.3）。每次安装在 Android Keystore 中生成独立、不可导出的 EC P-256 密钥。Python 绑定证书 DER SubjectPublicKeyInfo（SPKI）的 SHA-256，不依赖 IP 或 JSON 中的自报指纹。没有 HTTP 降级、重定向、共享私钥或无校验的已授权连接。首次无凭证身份探测尚未认证，其公钥只是候选值，核对确认后才建立信任。

首次配对时，用户逐位对照手机和桥接独立显示的**全部八位码**，在手机批准，并在控制端确认一致。CLI 要求输入 `yes`；MCP 只能在用户明确确认后提交 `confirm_pairing:true`。AI 不得通过手机控制工具读取核对码或代为批准，不得以服务端返回、等待时间代替用户确认，不得预先批准新配对。伪装服务器也能自称已获批准，因此只在手机点击不足以让控制端建立信任。之后每次连接自动验证已保存公钥，无需再次确认。

## 原生协议 phoneuse-sas-v1

传输加密与私钥持有证明由 TLS 提供；应用层使用哈希承诺及双方独立随机数生成 SAS 短码，对候选服务器公钥进行认证。这是应用专用协议，不是 ZRTP 实现，也不替代 TLS。承诺与 SAS 的设计思路可参考 [RFC 6189](https://www.rfc-editor.org/rfc/rfc6189.html#section-4.4.1.1)。

`P` 是连接中取得的 SPKI 指纹，`C`、`S` 分别是客户端与手机生成的 256 位随机数。三个值均编码为恰好 64 个小写十六进制字符。哈希输入为 ASCII 字符串，以单个 NUL 字节分隔，末尾没有 NUL：

```text
commitment = SHA256("phoneuse-sas-v1" || NUL || "commit" || NUL || P || NUL || C)
digest     = SHA256("phoneuse-sas-v1" || NUL || "sas" || NUL || P || NUL || C || NUL || S)
code       = zero_pad_8(big_endian_uint32(digest[0:4]) mod 100000000)
```

1. 桥接从 TLS 取得 `P`，生成 `C`，向 `/pair/request` 提交承诺、协议名和客户端名称。后续每个 TLS 连接均在发送任何 HTTP 数据及秘密前验证 `P`。
2. 手机接收承诺后生成 `S`，返回 `S`、协议名、配对 ID、领取秘密、有效期和轮询间隔。请求为 `committed`，不显示在批准列表，也不能签发凭证。
3. 桥接固定 `P,C,S`，本地计算核对码，再向 `/pair/reveal` 揭示 `C`。桥接不显示远端提供的核对码。
4. 手机用**自身 TLS 公钥**和 `C` 验证承诺。失败则永久拒绝该请求；成功则独立计算手机核对码，将请求改为 `pending` 并显示批准界面。
5. 用户完成双端核对确认后，桥接才允许 `/pair/status` 领取手机本地批准的凭证，并与绑定指纹原子保存。

客户端在取得手机随机数前提交承诺，并在固定另一方贡献后才揭示自己的随机数。转发针对伪造公钥的承诺会失败；攻击者建立两份不同内容的配对需猜中短码，每次概率约一亿分之一。全局每五秒最多一个新请求，最多 16 个存活请求、两分钟过期；每个请求只接受同一揭示值，不自动重试失败配对。拒绝、过期或服务重启后，不会把用户确认带入新的配对。这些限制也控制资源消耗，但不能消除拒绝服务攻击；人工比较和控制端确认始终是认证机制的一部分。

跨语言测试向量：`P=00*32`、`C=11*32`、`S=22*32`（十六进制字节）；承诺为 `9752824c0f5f6e1fb8abbea0ef2960d94e93db4125093766cdcb87bdf8b589e1`，短码为 `17242944`。

## 持久化、升级与换钥

手机密钥在服务和 App 重启后保留。凭证使用新的存储空间，使可能已暴露的 HTTP token 无法控制 HTTPS 服务。Python 自动将旧地址迁移为 HTTPS，但丢弃未绑定公钥的凭证和未完成请求。两端均需更新，并重新配对一次。

IP 变化不会改变公钥身份。密钥不匹配时在发送 HTTP 数据前失败，不会覆盖旧指纹。若确实重装或重置了设备，先独立核实，在手机撤销旧客户端，再执行 `python CLIENT forget-device --device-id DEVICE_ID` 显式删除本地绑定，重新配对。不得因网络报错自动删除或重绑。SPKI 绑定允许使用同一密钥更新证书；原生客户端的信任不依赖公共 CA 链、主机名或证书日期。手机密钥和身份、凭证偏好设置不参与备份迁移。

## 浏览器边界

浏览器直连使用 HTTPS，以及 Secure、HttpOnly、SameSite=Strict Cookie，保留严格的 IP Host 和 HTTPS Origin 检查。网页 JavaScript 无法替浏览器认证不可信证书。浏览器原有六位授权码不是原生八位 SAS 协议，不能替代证书信任。使用浏览器前需独立建立证书信任，不应盲目跳过警告；需要自动完成原生信任流程时使用 MCP／CLI。本次不添加本地网页代理、域名配置或公共 CA。

验证包括 Kotlin/Python 共同测试向量、真实回环 TLS、公钥替换时发送前拒绝、本地确认门槛、旧凭证迁移，以及 Android Keystore TLS、配对、API、MCP 仪器测试。这些是回归证据，不代表独立密码学审计。
